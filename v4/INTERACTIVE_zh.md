# 在 Ubuntu 的 R 中逐行运行 v4

完整代码是同目录的 [interactive_analysis.R](interactive_analysis.R)。其中每个非空代码行都有中文注释。旁边的 [interactive_support.R](interactive_support.R) 负责日志、会话来源、错误和恢复检查，同样逐行注释。

这次改变的是操作入口。原 settings.R、四个阶段、R/底层算法、Stan文件、两张输入表、四张折表、先验、种子、AUC定义及三项BH均保持原样。

## 开始方式

在 Ubuntu 上使用已按 UBUNTU_zh.md 准备的 R 4.6.1 环境，打开一个干净的 R/RStudio 会话。打开 interactive_analysis.R，把第1段的路径改成自己的目录，例如：

~~~r
project_dir <- "/home/minfei/project/v4" # 改成自己解压后的v4目录；在开始执行前完成修改。
~~~

随后从文件第1段开始执行当前行或选中的完整表达式。普通语句可以逐行；带花括号的代码块请整块选择。没有必要把现有01–04入口中的commandArgs代码粘到R控制台，也不需要在R里调用Rscript。

不要只复制本说明中的一两行就认为已经启动完整流程；完整执行顺序以 interactive_analysis.R 为准。它本身就是可运行的R代码，注释不是占位步骤。

如果整份source交互文件，它会在完成路径配置后顺序执行全部计算。逐行学习时，先停在各查看语句，确认对象含义，再主动执行包含拟合的代码块。

## 八段分别做什么

| 段落 | 会做什么 | 执行后看什么 |
|---|---|---|
| 1 环境与路径 | 设置两个目录；加载并绑定实际代码身份；核对79个包版本和命名空间 | 模型、路线、权重、采样设置、种子、输出位置 |
| 2 读取资料 | 调用原prepare_stage，读取六张冻结CSV并检查 | 153条记录、51/50物种、105/40/8三类记录、折表 |
| 3 分类与编码 | 查看已有分类、三种编码和任务清单 | 145条/48物种点值集合、Site151排除、128个任务 |
| 4 展开一个CV任务 | 选binary/M1/五折/第1折，依次看物种、记录、矩阵、先验、种子，再拟合并生成留出预测 | 一次正式任务的全过程；诊断必须PASS |
| 5 完成其余任务 | 原fit_stage循环执行128项，已有同身份示例缓存会复用 | 全部诊断、完整OOF、全数据预测、PPC与清单 |
| 6 评价与检验 | 原evaluate_stage产生指标、bootstrap和BH3，并保存阶段记录 | 120行折指标、16行汇总、30项检验、10个三项家族 |
| 7 预测与绘图 | 查看2920行全面板预测与PPC提示，调用原plot_stage | 七份PDF和图源 |
| 8 最终核对 | 原check_complete_outputs核对全部对象和输出 | COMPLETE或COMPLETE_WITH_REVIEW_FLAGS |

第4段不是另加一个独立模型：它取自原128任务清单，使用相同FitID、seed、训练物种、设计及缓存路径。第5段仍遍历完整清单，遇到这一项时验证并复用。第一次从零完整运行实际仍为128项拟合。

## 怎样查看另一路线

默认展开分类M1。若希望展开定量路线，有两种明确做法：

- 在开始新会话之前，将文件中的 route 赋值改为 joint_bb，再从第1段执行。
- 保持源文件不变，到第4段时在控制台用下面这句替代默认的route赋值，再依次执行第4段其余代码。

~~~r
route <- "joint_bb" # 只改变这次展开查看的代表任务；后续自动阶段仍运行两路线与四个模型。
~~~

不要在会话已经绑定来源之后一边修改磁盘文件、一边继续使用旧内存函数；入口会拒绝这种混用。修改settings.R后应重新开始干净会话，并按原规则使用新的输出目录。

控制台中选择代表任务不是更改正式分析范围。不要直接修改spec$formula、spec$data或临时放宽SAMPLING后尝试写入正式缓存；代表性拟合前会与冻结状态重建的规格及实际Stan输入比较。

## 中断后怎样恢复

准备阶段已经完成时，重新打开干净R会话，重新执行主文件第1段，保持相同project_dir和output_dir，然后在R中执行：

~~~r
state <- interactive_step("resume", root, output_dir, interactive_refresh_state(root, output_dir)) # 读取并核对已保存的准备状态，恢复磁盘设置。
run_plan <- task_plan(state) # 重新取得相同的128项任务清单。
print(table(run_plan$Design)) # 确认仍为8个full、40个fivefold、80个tenfold任务。
~~~

接着从第5段继续。诊断和身份一致的缓存会被复用；未完成任务继续拟合。若已完成拟合、只想继续评价或画图，可以从第6或第7段开始，其前置阶段记录会被核对。

若连第2段都没有完成，先执行第2–3段。若诊断失败，先查看失败项和日志，不通过修改门槛强行继续。新输出目录不要和其他R会话或进程同时写入。

## 状态和日志在哪里

- output_dir/interactive_logs/：每个执行块一个追加日志，记录主R会话输出、消息和警告。
- status.json：RUNNING、某一步_COMPLETE、FAILED或INTERRUPTED；只有通过最后的完整验收才写全流程COMPLETE。
- interactive_example_diagnostics.csv、interactive_example_predictions.csv：代表性单折中间表，不代替完整CV输出。
- interactive_sessionInfo.txt：完成时的R会话环境。
- 原fit/evaluate/plot三个receipt及fit_manifest：继续采用原实现，没有删去。
- status.json另外记录两份交互代码的SHA256；原模型分析身份不因新增教学入口而改变。

R级日志可以查看模型调用与诊断消息；极端进程崩溃或操作系统直接终止时，不应期待R错误处理器还能继续写完日志。恢复时以已落盘的缓存、诊断和检查为准。

## 本次验证范围

从干净R进程逐个表达式执行这份实际主文件；普通R启动测试不提供--file参数。代表性任务使用经过数据、模型与抽样参数核对的既有原生后验缓存，批量任务使用明确标记的替身，以避免本次启动研究数据拟合。指标、P/BH3、图件和最终验收使用原有函数实际执行。

另独立检查报错/中断、sink与连接恢复、参数恢复、公式权重变更、加载后修改源文件及缺失产物。详细测试记录在仓库 validation/v4_interactive。不要把这些测试的COMPLETE状态称为新的128项真实拟合已经完成。

原先的四个Rscript入口保留，供自动复现使用；两个入口调用同一套模型与评价函数。
